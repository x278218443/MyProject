# 本地 PSD 转 UI（独立版）

Unity 菜单：`UIConvert > Local PSD Converter`。

所有生产脚本、PSD 导出脚本、配置和程序集定义都在本目录。Editor 程序集 `Starlight.LocalUIConverter.Editor` 引用 Unity UI、TextMeshPro 及本工具自带的 `Starlight.LocalUIConverter.Annotations` 节点描述程序集，布局和来源映射使用 .NET JSON 序列化，避免 Unity JsonUtility 的递归层级限制。节点描述组件放在独立程序集内，使其可在 Prefab 上手动添加；成功生成 Bind 后会全部移除。无需安装或启用旧转换工具，也不读取旧工具的配置、替换表或后处理注册表。Bind 生成功能按项目约定可选调用 `Starlight.Core.Editor.ScriptGenerator.Generate`；通过运行时发现调用，不引入业务程序集引用或修改原生成器。

## 使用

1. 主界面显示 PSD、效果图、输出名称、输出目录以及 FunctionID、预设体目录、脚本目录；本地配置、文字模式、Python 环境收纳在默认折叠的“其他选项”中。需要修改替换规则时，在其他选项中点击“编辑配置 / 替换规则”。
2. 选择 PSD，可选效果图作对照。效果图和输出名称初始为空；PSD 完整文件路径保存在按项目区分的本机 EditorPrefs 中，浏览、拖入、手动修改或清空均会立即保存，重新打开窗口或 Unity 后恢复。PSD 浏览窗口也会使用本机 EditorPrefs 中的上次选择目录，浏览、拖入或输入有效 PSD 路径均会更新目录记录。
3. 首次使用可展开“其他选项”，在 Python 环境中点击“检查环境”。需要 Python 3.11 或更新版本；可以填写可执行文件完整路径。缺少依赖时点击“安装 / 补齐依赖”。首次安装需联网，安装后解析在本地完成。依赖固定为 `psd-tools[composite]==1.17.1`。
4. 点击“解析 PSD / 预览”，检查图层报告和警告。
5. 填写输出名称，点击“生成预设体”。主界面输出目录可直接输入或浏览选择，初始值取本地配置的 `outputRoot`，默认 `Assets/__Temp`。本次选择不会修改共享配置，覆盖同名结果前会确认。

Unity 内安装失败时，可在资源管理器双击本目录的 `InstallDependencies.bat`，输入 Unity 工具中配置的同一个 Python 可执行文件路径（可以带引号），回车开始安装。默认优先使用存在的 `E:\Python\python.exe`，否则使用 PATH 中的 `python`。脚本检查 Python 3.11+、补齐 pip、安装固定版本的 PSD 导入/反导依赖，最后调用工具的 `--check` 验证；成功或失败均保留窗口显示结果。也支持命令行传参：`InstallDependencies.bat "E:\Python\python.exe"`。此脚本补齐 Python 库，不安装 Python 本体。

### 在 Unity 外安装 Python 依赖（Windows）

如果受监管的 Unity 无法执行安装，可在资源管理器中双击本目录的 `InstallDependencies.bat`。脚本优先使用 PATH 中的 `python`，找不到时尝试 `py -3`；检查 Python 3.11+、补齐 pip、安装与窗口按钮相同的 `psd-tools[composite]==1.17.1`，最后执行同目录 `psd_export.py --check`。脚本结束会停留显示结果，失败返回非零退出码。

如果窗口已指定 Python，需在命令提示符中为 bat 传入相同的解释器路径（不能传 Python 安装目录）：

```bat
InstallDependencies.bat "C:\Users\YourName\AppData\Local\Programs\Python\Python311\python.exe"
```

安装成功后，将脚本输出的 `python.exe` 完整路径填入“其他选项 → Python 环境 → 可执行文件”，再点击“检查环境”。首次安装需要能访问 pip 软件源；脚本遵循本机 pip 的镜像、代理配置，不需要从 Unity 发起安装。Python 本体需预先安装；若系统也限制外部安装，请由管理员按机器管理要求执行。

生成在临时预览场景中完成，完成或取消后释放该场景，结束时打开结果的 Prefab 编辑模式。

生成的主预设体根节点默认全屏拉伸：Anchors Min `(0,0)`、Max `(1,1)`，四边偏移均为 0，跟随父 RectTransform 尺寸变化。子节点仍保留 PSD 布局。反导 PSD 时，独立根节点没有父级尺寸则使用原布局 JSON 的画板尺寸。

## 独立配置与规则

本目录自带独立的 `LocalUIConverterSettings.asset`，已复制当前项目的 47 条通用预设体映射和 `txt_` 组件前缀映射。它们是一次性配置快照，后续修改旧表不会影响本工具。新配置直接引用项目的游戏预设体、运行时组件脚本、字体及材质；这些是生成结果使用的项目资源。

- `componentRules`：按节点名称前缀绑定指定 Graphic 组件，支持 TMP 子类。未命中时图片生成 Image、文字生成 TextMeshProUGUI；图片节点有直接文字子层时添加 Button。
- `prefabRules`：按节点全名替换通用预设体，保留层级位置并按占位尺寸缩放。
- `G_`：共享同名去掉 `G_` 后的基节点图片；未找到基节点时保留原图。
- `P_`：提取子预设体；同名项依次使用原名、`_0`、`_1` 文件名。支持嵌套子预设体。
- `G_P_`：引用本次生成的对应 `P_` 子预设体，按占位尺寸缩放；缺少对应项或循环依赖时保留原节点并提示。
- 字体：`fontRules` 精确映射优先，然后匹配字体资源名称/字体族/源字体名；可从匹配的 TTF/OTF 自动创建 TMP 字体，找不到时使用 `defaultFont` 或 TMP 默认字体并提示。
- 描边：在 `outlineMaterialFolder` 按字体 atlas 和描边颜色匹配已有材质；找不到时复制字体默认材质，按 PSD 描边颜色和粗细近似生成独立 `.mat` 并赋给文本。命名为 `{字体默认材质名}-{描边RGB大写十六进制}.mat`，例如 `Font-A Material-A5-3D3D3D.mat`；同名被不同粗细等材质占用时，在颜色前加序号，如 `Font-A Material-A5-2-3D3D3D.mat`。自动生成的材质按字体、颜色及归一化粗细复用，不同粗细分别保存，不修改字体默认材质或已有手工材质。

运行顺序：本地解析 → 生成图层与组件 → 共享图片 → 通用预设体替换 → 子预设体提取/共享 → 保存。替换成功且无任何生成结果依赖的 G_ 临时图片会被清理。

## 文字尺寸与 PS 效果

可编辑文字保留自动换行，使用最终匹配的 Unity 字体在不限宽条件下测量原文所需宽高。文本框只扩大不缩小，宽度向上取整并保留 1 个画布单位的余量，保持中心位置，避免 PSD 字形边界过窄将单行标题挤成多行。原文中的显式换行保留。

读取文本、字体、字号、颜色、对齐、行距和字距；混合字样式取首段。RGB 描边优先匹配已有字体材质，缺少时自动生成。自动材质粗细与项目 `TmpCustomEditor.CalcThickness` 使用相同换算约定，但在本工具内部独立实现：`ratio = atlasPadding / 采样字号`，普通 Shader 为 `PSD描边像素 × 0.5 / (当前字号 × ratio)`，Mobile Shader 为 `PSD描边像素 / (当前字号 × ratio)`。结果限制在 0～1，超出范围时警告，需要更粗描边时可增加字体图集 Padding。该换算仍为近似值，PSD 描边位置、柔化等效果需人工对照。已有手工材质仍按原来的图集和颜色规则匹配，保留其人工调整的宽度。渐变等无法直接应用的可编辑文字特效会提示差异。

支持将文字的上下双色线性“渐变叠加”转为 TMP 顶点渐变，可与描边材质同时使用，文字仍可编辑。要求 RGB 双色色标、角度 90/270 度（支持反向）、图层对齐、缩放 100%、零偏移、普通混合。文字底色及自身透明度保留在 TMP 的 `color`；原始渐变 RGB 单独写入 `colorGradient`，渐变叠加不透明度乘以统一的透明度色标值写入渐变 Alpha（例如 70% 写入 0.7）。不预先混合底色与渐变色。两个色标未恰好位于 0/100% 时，也保留两端颜色及透明度并按全高度线性渐变近似，报告会提示色标外纯色区域的差异。色标中点不为 50% 时也导入，保留两端颜色及透明度，以 TMP 的线性渐变近似，并在报告中说明过渡曲线差异。TMP 会乘算两组颜色，效果与 PS 的普通叠加可能不同。当前仅支持透明度色标数值一致的渐变。不符合条件时保留基础文字并在解析报告中提示，可选“文字作为图片”保留外观。TMP 渐变按字符四角插值，多行或不同字高不保证与 PS 整个图层的渐变完全一致；当前反导 PSD 时渐变文字使用实际渲染图保留外观。

选择“文字作为图片”时，将文字和支持的图层特效栅格化，原名节点下增加 `__PSD_TextRaster` 图片子层，避免 `txt_` 组件规则把图片绑定为文字。

图片导出支持解析库能够处理的蒙版和特效，扩大范围容纳阴影/发光。复杂混合、剪贴、调整层、组蒙版和组特效无法保证与 Photoshop 一致，需结合报告人工检查。适合整理好的程序切图 PSD。

效果图仅作对照，不推断布局或填补缺失图层。PSD 合成预览使用文件保存的合成图，不代表生成结果已经像素一致。

## FunctionID、工程目录与 Bind 脚本

FunctionID 支持字符串。结束输入（回车或移出输入框）后，只给空的路径框补默认值：

- 预设体目录：`Assets/Bundles/UI/Prefab/{FunctionID}`。
- 脚本目录：`Assets/Scripts/Game/Module/Function/{FunctionID}`。
- 整理切图的美术切图目录：`Assets/Bundles/UI/UIImages/{FunctionID}`。

FunctionID 使用按项目区分的本地 EditorPrefs 保存，再次打开自动恢复并补齐空路径。右侧 Clear 按钮会清空 FunctionID、本地记录以及关联的预设体目录、脚本目录、美术切图目录，同时使旧整理方案失效；不会删除磁盘文件。

已填写的路径不被覆盖，路径框均可浏览选择。FunctionID 作为单个目录名使用，不允许路径分隔符。

“移动预设体到工程目录”和“整理切图”独立成一行。“移动预设体到工程目录”将本次生成的主预设体及 P_ 子预设体一并移入指定目录，保持 GUID 和嵌套引用。同名目标会在移动前阻止整次操作，不覆盖已有文件；移动出错会尝试将已移动项移回原位。移动后整理切图会继续跟踪这批预设体，不要求它们仍在临时输出目录。

“生成Bind脚本”和“生成Bind脚本(组件)”位于下一行：

1. 使用当前生成预设体的文件名作为类名，在 `{脚本目录}/UI/{预设体名}.cs` 检查主脚本。
2. 文件不存在时创建 `namespace Starlight.Game` 下的同名 partial 类；普通按钮继承 `UIFunction`，组件按钮继承 `UIComponent`。已有文件不覆盖，已有类的继承与按钮类型冲突时提示错误。
3. 新脚本等待 Unity 编译完成，任务在程序集重载后自动继续。
4. 在预设体根节点挂上对应 UI 类及 VariableBinding，选中根节点，调用项目 ScriptGenerator 的 Generate(true, true, false)，并保存预设体。
5. Bind 文件按项目生成器的约定输出到主脚本旁的 `UI/Bind/` 目录。

该流程需要当前项目提供 UIFunction/UIComponent、VariableBinding 和 ScriptGenerator。预设体名称必须是有效 C# 类名。生成 Bind 会自动保存当前目标预设体中的编辑和节点描述；若打开的是另一个有未保存修改的预设体，需要先保存它。存在 Unity 编译错误时请修复后重新点击。

主脚本新建及等待编译状态存储在 Editor 会话中，跨程序集重载恢复；重启 Editor 后可重新点击按钮继续。窗口按 GUID 跟踪生成结果，移动不影响后续 Bind 和切图整理。

## 加载已有结果与编辑节点描述

Codex 研判按输出名称归档到 `__Temp/LocalUIConverter/CodexReview/{输出名称}/{任务ID}/`，每次任务保留独立请求与建议，不覆盖旧结果。“读取 Codex 建议”不再要求先复制请求：解析或加载已有目录后，填写相同输出名称，即可直接查找最近一次已完成且布局匹配的建议；没有当前候选时自动从原请求恢复候选，无需再次调用 OmniParser。人工修改、否决过的候选保留。新请求尚未完成时仍可读上次完成结果。旧版随机 ID 目录会在 PSD 来源、图层身份和布局匹配时自动关联到该输出名称。PSD 图层布局或候选顺序/位置变化时拒绝套用，避免把编号建议写到其他节点。仅修改预设体不影响此复用。

主界面的“加载已导入的目录”选择本工具的具体导出目录，例如 `Assets/__Temp/MyWindow`，而不是其父目录或 `Prefabs` 子目录。加载后自动填写输出名称与输出目录，恢复布局、已生成预设体（包括按 GUID 跟踪的已移动预设体）、整理切图范围及本机保存的审核候选。无需重新导入 PSD 即可继续 Bind、整理切图、反导 PSD。

解析后只要已填写输出名称与输出目录，关闭工具窗口会将进度保存至项目根目录 `__Temp/LocalUIConverter/Workflows/`。其中包括候选匹配、类型、绑定名、功能描述和人工审核状态。尚未生成预设体时也会创建可选择的输出目录；重新打开工具，选择该目录即可继续审核。旧导出目录没有工作流存档时可从 `layout.json` 恢复后续交付流程。若原 PSD 已变化，重新生成前需重新解析；原 PSD 暂不可用时仍可加载已有布局。候选预览依赖原解析缓存，缓存被清理后需重新解析才能重新识别。

生成预设体时，已标记的节点会带上 `LocalPSDNodeDescription`（Add Component 菜单 `Local UI Converter/节点描述`），只有“类型”和“描述”两个可编辑字段。可在未识别的节点、手工新增节点上添加该组件，也可修改或删除现有标记。新增“纯节点描述”（`Description`）类型，用来备注分组、占位、显示条件等业务信息：保留节点名称与组件，不自动生成该节点的 Bind 字段；其子节点仍可独立标记和绑定。描述参与存档/恢复，并在生成 Bind 后输出到 UI Spec 的“有备注的未绑定节点”，方便 Codex 编写业务逻辑。Hierarchy 显示灰色“备注”标签，并支持折叠汇总。`None` 保持旧版只记录描述、不指定组件的行为；控件类型为 Button、Text、Scroll、Toggle、Slider。描述编辑以 Prefab 编辑模式中当前结果为准。

Hierarchy 右侧显示彩色类型标签。节点折叠后，隐藏标记汇总到当前可见的最近父节点；多层折叠逐级向上汇总，展开后标签回到实际可见节点，不在各层重复。父节点自身的标记与隐藏子节点按类型合并计数，如“按钮×2”“文字×3”，悬停可查看节点相对路径和描述。不同 Hierarchy 窗口独立按各自的展开状态显示，搜索模式仅显示匹配节点自身的标记。宽度不足时以 `+N` 汇总剩余类型，悬停仍可查看详情。

点击任一“生成Bind脚本”按钮时，会保存目标 Prefab、按标记补足所需组件、为不符合绑定命名规则的标记节点生成名称，并更新 `__Temp/LocalUIConverter/NodeDescriptions/{预设体文件名}.json`。存档还会同步到原有 GUID 节点映射，供 Bind 和 UI Spec 使用。同名标记按节点 GlobalObjectId 分别存档。同名节点的绑定由项目原有生成器处理，描述存档可以同时保留多条同名节点的备注。Bind 成功后移除目标 Prefab 上的所有节点描述组件并保存；失败时不会提前清理描述。正式资源请使用成功生成 Bind 后的预设体。

“读取节点描述”优先操作当前 Prefab 编辑页，未打开编辑页时操作工具当前加载的主预设体。按存档中的节点 GlobalObjectId/fileID 恢复描述组件，重命名、换父节点或移动预设体仍可识别，已有组件及编辑不会被覆盖。旧工具结果也能从 GUID 映射中恢复原有描述。对读回的标记进行修改、添加或删除，再生成 Bind 就会覆盖存档；删除全部标记也会写入空存档，之后不会复活旧标记。已清理组件但未重新读取时，重复生成 Bind 会继续使用现有存档，不将其误清空。节点被删除后重建不按同名强行恢复，另一个同名但 GUID 不同的预设体不会覆盖当前存档。

## 资源整理

生成成功后自动显示“资源整理”。也可直接点击主界面操作区的“整理切图”打开，无需展开其他选项或再次解析 PSD。

1. 导出目录选择含 `Textures` 和 `Prefabs` 的生成结果目录。
2. 通用图片默认为独立配置中的 `commonTextureRoot`，允许留空；美术切图目录未填写时随 FunctionID 自动填充为 `Assets/Bundles/UI/UIImages/{FunctionID}`，也可以手动修改。执行整理时自动创建尚不存在的美术目录；仅检查方案时不创建目录。
3. 点击“检查整理方案”，查看复用、移动、保留及冲突清单。
4. 点击“执行整理”。执行时会检查方案是否过期；当前打开的预设体有未保存修改时，需先保存。

同名文件匹配忽略目录层级及大小写，通用图片优先于美术图片。未匹配的新增 `IMG_` 图片按原始文件尺寸分类：宽大于 `TextureRuleSuite.MaxImageSize` 或高大于其一半时移动至美术目录的 `BG/`，其余移动至 `IMG/`；等于边界时仍放入 `IMG/`。独立工具通过运行时读取项目校验类的常量，项目未提供该类时默认 512，即宽大于 512 或高大于 256 进入 `BG/`。新增 `BTN_` 图片仍移动至 `BTN/`，其他前缀保留在输出目录。检查方案只预览目标，执行时自动创建所需目录。移动使用 AssetDatabase，保持原 GUID。

已检查并改进原有整理流程中的以下问题：

- 同一库内有多个同名文件时列为冲突，阻止执行，避免任意取第一个。
- Sprite 与 Texture2D 按实际类型匹配，Sprite 多子资源优先按名称唯一匹配，不使用其他文件的 fileID，也不回退到任意首项。
- 遍历预设体所有序列化引用，包括隐藏字段、数组和嵌套预设体；子预设体先保存，再处理父预设体。
- 仅在引用替换全部保存后清理重复原图，并检查整个项目/包的依赖及未保存场景中的实时引用；仍有引用的原图会保留。
- 输出目录和图片库不得互相包含；不覆盖目标已有文件，不使用原始文件删除兜底。
- 生成布局 JSON 的图片路径随移动/复用同步更新。

整理可取消；已保存的替换和已完成的移动会保留，可重新检查方案后继续。可以关闭“清理重复原图”，仅执行引用替换和分类移动。

在不安装旧工具的 Unity 隔离项目中验证了：多处共享 Sprite、隐藏字段与数组、Texture2D 引用、嵌套预设体、GUID 保持、外部预设体和未保存场景引用保护、同名冲突、类型冲突、过期方案拒绝，以及窗口初始折叠状态。

## 导出 PSD（试用）

在“其他选项 → PSD 反导（试用）”点击“导出 PSD”。默认目录为**项目根目录下的 `__Temp/PSD`**（不是 Assets 内），可通过旁边的浏览按钮更改。使用当前生成并按 GUID 跟踪的主预设体；预设体已经移动到工程目录也可导出。请先保存 Prefab 编辑页中的修改。

导出完成后自动打开所在目录并选中 PSD。同名文件保留，新的结果自动追加序号。输出包括：

- `.psd`：当前名称、分组和布局对应的设计文件。
- 同名 `.roundtrip.json`：PSD 图层 ID 到稳定节点 ID、程序名称、组件替换规则的映射。请与 PSD 一起交付美术并保留相同文件主名，再次导入时工具会自动读取。
- 同名 `.report.txt`：来源缺失、文字栅格化等信息。

**原始 PSD 与 fileID 映射：**初次生成后，在项目根目录的 `__temp/LocalPSDUI/{预设体GUID}.json` 保存“节点 GlobalObjectId（包含 fileID 和预设体身份）→ 初始图层名称、原 PSD 图层 ID、稳定节点 ID、组件替换规则”。旧版 ProjectSettings 记录会在读取时自动迁移，新记录只写入 __temp。原稿按内容归档到 `__Temp/PSD/.sources`，不依赖 Library 缓存。重命名、调整父级和移动预设体可继续匹配。新增、删除后重建的节点使用新 ID，不仅凭同名强认成旧节点。

旧版本生成、尚无映射的预设体，可结合主界面选择的原始 PSD 和旧布局，通过唯一名称、图片、文字内容及通用预设体引用建立首次映射；不唯一的匹配会写入报告。无需为建立映射而覆盖已有预设体。

**通用组件与子预设体：**通用组件优先恢复替换前的原稿图层，再套用当前 Unity 名称、位置和尺寸；不展开组件的程序内部节点。映射中的规则键独立于显示名称，再次导入时按规则键恢复通用预设体引用。P_ / G_P_ 规则键也随映射保留。

**当前试用边界：**普通图形按当前 UI 渲染成图片层；能匹配到原稿且内容、字号不变的文字，尽量保留原生 PS 文字和原稿字体/效果，其余文字导出为图片并提示。原稿中的形状、智能对象和复杂特效尚不保证完整无损恢复；Unity 的特殊材质、蒙版、旋转等显示与语义需人工检查。原图层已经不可识别时导出当前外观并提示。通用组件内部的运行时内容不自动回写通用组件库。

这是设计文件往返试用，并非任意 Unity 组件、脚本字段和事件的无损增量同步；再次生成沿用当前生成流程。请先使用副本验收。已在隔离 Unity 项目中验证：改名/调整父级后的 fileID 识别、预设体移动、分层 PSD、原生标题文字、通用组件恢复与再次替换、程序命名/分组、空组与隐藏节点。

- `LocalUIConverterSettings.cs` / `.asset`：独立配置。
- `Starlight.LocalUIConverter.Editor.asmdef`：Editor 程序集隔离。

解析缓存位于 `Library/LocalUIConverter/<本次ID>/`。修改 PSD 或文字模式后需要重新解析；关闭窗口可通过“加载已导入的目录”恢复本机进度。生成结果包含独立图片和布局 JSON；清理解析缓存不影响已生成的预设体。跨机器重新生成时应从原 PSD 重新解析，继续编辑描述则需要同时携带 `__Temp` 中的节点描述存档和来源映射。
