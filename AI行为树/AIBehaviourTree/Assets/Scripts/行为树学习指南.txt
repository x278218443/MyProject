一、什么是行为树？（通俗解释）
================================================================================

想象你是一家餐厅的经理，你要管理一个服务员的工作流程：

  服务员的"程序"：
  ┌─────────────────────────────────────────────┐
  │ 每次循环：                                     │
  │   if 有客人要结账？→ 去结账                       │
  │   else if 有客人要点菜？→ 去点菜                  │
  │   else → 在餐厅里巡逻检查卫生                     │
  └─────────────────────────────────────────────┘

这就是一个最简单的行为树！每个"if"都是一个判断节点，每个"→"都是一个动作节点。

在游戏AI中，行为树就是让NPC"思考"的系统：
  - 每帧（或每隔几帧）运行一次
  - 从根节点开始，根据条件选择不同的行为
  - 让NPC看起来有"智能"

二、核心概念详解
================================================================================

1. 节点状态（NodeState）
   ─────────────────────
   每个节点执行完必须返回三种状态之一：

   Success ✅ — 这个节点成功完成了
     例：条件"玩家在范围内"满足了
     例：动作"移动到目标点"完成了

   Failure ❌ — 这个节点失败了
     例：条件"玩家在范围内"不满足
     例：动作"攻击"因为没有目标而无法执行

   Running ⏳ — 这个节点还在执行中
     例："正在移动到目标点"（需要多帧才能完成）
     例："正在攻击"（持续进行中）

   重要：Running 是行为树最强大的特性！
   它让NPC可以执行"持续性"动作，而不是每次都从头开始。


2. 组合节点（Composite）
   ─────────────────────

   【Sequence 顺序节点】— 代表 AND 逻辑
   ┌────────────────────────────────────────────────┐
   │  所有子节点必须都成功，整体才算成功                    │
   │                                                    │
   │  子节点1 ──成功──→ 子节点2 ──成功──→ 整体: Success  │
   │    │                 │                              │
   │   失败              失败                             │
   │    ↓                 ↓                              │
   │  整体: Failure    整体: Failure                     │
   └────────────────────────────────────────────────┘

   举例：Sequence[ 玩家在范围? → 移动过去 → 攻击 ]
   = "只有玩家在范围内，且移动到了，且攻击了，才算成功"


   【Selector 选择节点】— 代表 OR 逻辑
   ┌────────────────────────────────────────────────┐
   │  只要有一个子节点成功，整体就算成功                    │
   │                                                    │
   │  子节点1 ──失败──→ 子节点2 ──成功──→ 整体: Success  │
   │    │                 │                              │
   │   成功              失败                             │
   │    ↓                 ↓                              │
   │  整体: Success    继续尝试子节点3                     │
   └────────────────────────────────────────────────┘

   举例：Selector[ 追击? → 巡逻? → 发呆 ]
   = "能追击就追击，不能就巡逻，不能就发呆"


3. 条件节点 vs 行为节点
   ─────────────────────

   条件节点（Condition）：
   - 只返回 Success 或 Failure
   - 不做任何动作，只做"检查"
   - 一瞬间完成，不会返回 Running
   - 例："玩家在攻击范围内吗？"

   行为节点（Action）：
   - 可以返回 Running（持续性动作）
   - 执行实际的游戏逻辑
   - 例："移动到目标点"、"攻击敌人"


4. Blackboard 黑板（共享数据）
   ─────────────────────

   黑板是节点之间共享数据的方式：
   - 节点A：检测到玩家位置 → 写入黑板
   - 节点B：从黑板读取玩家位置 → 向那个方向移动

   这样节点之间不需要直接引用，降低了耦合。


5. 优先级
   ─────────────────────

   在 Selector 中，子节点从左到右执行：
   - 最左边的 = 最高优先级
   - 最右边的 = 最低优先级（兜底方案）

   我们的守卫AI：
   攻击(最高) > 追击(中) > 巡逻(最低)

三、代码文件说明
================================================================================

Assets/Scripts/
├── Core/                        ← 行为树核心框架（可复用到其他项目）
│   ├── BTNode.cs               ← 节点基类 + NodeState枚举
│   │                              定义了 Tick()、Reset() 等核心接口
│   │
│   ├── BTComposite.cs          ← 组合节点
│   │   ├── BTSequence          ← 顺序节点（AND逻辑）
│   │   └── BTSelector          ← 选择节点（OR逻辑）
│   │
│   └── BTRoot.cs               ← BehaviourTree类（行为树容器+黑板）
│                                  包含 Blackboard 内部类
│
├── Conditions/
│   └── BTIsPlayerInRange.cs    ← 判断玩家是否在指定范围内
│
├── Actions/
│   ├── BTPatrol.cs             ← 巡逻行为（在路径点之间移动）
│   ├── BTChase.cs              ← 追击行为（朝玩家移动）
│   └── BTAttack.cs             ← 攻击行为（面向玩家+伤害）
│
├── BTGuardAI.cs                ← 主控制器（组装行为树+挂载到NPC上）
│   └── BTCondition             ← 内联条件节点（用Lambda快速创建）
│
├── Player.cs                   ← 玩家控制（WASD移动，用于测试）
│
└── 行为树学习指南.txt            ← 你正在看的这个文件

四、Unity中的使用步骤
================================================================================

步骤1：创建场景
  1. 打开 Unity → 新建场景
  2. 创建一个 Plane 作为地面（缩放设为5,1,5）

步骤2：创建NPC
  1. 创建 → 3D Object → Cube
  2. 命名为 "Guard"
  3. 拖上 BTGuardAI 脚本
  4. 设置 Tag 为 "Untagged"（NPC不需要特殊Tag）

步骤3：创建巡逻点
  1. 创建 → Empty（空物体），命名为 "Waypoint_0"
  2. 放在NPC附近某个位置
  3. 重复创建 Waypoint_1, Waypoint_2, Waypoint_3（围成一个圈）
  4. 选中Guard → 在Inspector的 Waypoints 数组中拖入这4个点

步骤4：创建玩家
  1. 创建 → 3D Object → Sphere
  2. 命名为 "Player"
  3. 拖上 Player.cs 脚本
  4. ⚠️ 重要！设置 Tag = "Player"
  5. 放在场景中的某个位置

步骤5：调整视角
  1. 把 Main Camera 放在一个斜上方的位置（能看到整个场景）
  2. 比如 Position: (0, 12, -10), Rotation: (50, 0, 0)

步骤6：运行！
  1. 点击 Play
  2. 用 WASD 控制玩家移动
  3. 观察 Console 日志，看守卫AI的行为切换

五、如何观察AI运行
================================================================================

观察重点：
  1. Console 日志 — 每次行为切换都会打印日志
     "[条件] 感知范围内?:" 看到 ✓ 或 ✗
     "[巡逻] 到达巡逻点" 巡逻行为
     "[追击] 发现玩家！" 追击开始
     "[攻击] ★ 对玩家造成 10 点伤害！" 攻击进行中

  2. Scene 视图 — 选中Guard对象，可以看到：
     - 黄色球体 = 感知范围（10米）
     - 红色球体 = 攻击范围（2米）
     - 青色线条 = 巡逻路线

  3. Game 视图 — 左上角有操作提示

行为切换流程：
  ┌─────────┐     玩家靠近     ┌─────────┐
  │  巡逻中  │ ──────────────→ │  追击中  │
  └─────────┘                  └─────────┘
       ↑                           │
       │     玩家跑远               │ 玩家进入攻击范围
       │     ┌──────────┐          ↓
       └─────│  继续巡逻  │ ← ┌─────────┐
             └──────────┘   │  攻击中  │
                             └─────────┘

六、进阶学习方向
================================================================================

当你理解了这个Demo之后，可以继续学习：

1. 装饰节点（Decorator）
   - Inverter: 反转子节点结果（Success→Failure）
   - Repeat: 重复执行子节点N次
   - Cooldown: 冷却时间，N秒内不允许再次执行
   - Probability: 按概率执行（比如70%追击，30%逃跑）

2. 更复杂的组合节点
   - Parallel（并行节点）: 同时执行多个子节点
   - RandomSelector: 随机顺序执行
   - WeightedSelector: 带权重的选择

3. 状态机 vs 行为树
   - 传统方案：有限状态机(FSM)
   - 行为树更适合复杂AI
   - 两者可以混合使用

4. 实用工具
   - Behavior Designer（Unity Asset Store 插件）
   - NodeCanvas
   - 自己写可视化编辑器

5. 高级技巧
   - 行为树缓存（避免每帧重新创建）
   - 异步节点（等待动画播放完毕等）
   - 行为树调试可视化工具
